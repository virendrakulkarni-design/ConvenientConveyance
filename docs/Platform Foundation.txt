SDD-01: Platform Foundation
Version: 0.1 | Status: Draft | Wave: 0 | Depends on: SDD-00 decisions D-001 to D-035 | Open decisions that touch this SDD: D-041 (CI platform), D-042 (multi-tenancy) Purpose: create the repository, tooling and runtime base that every other module builds on, so that all later SDDs can assume these conventions exist and behave exactly as written here.
1. Scope
In scope: repository layout; tooling configuration; environment configuration; application bootstrap for api and worker; request context; error handling; API conventions; database roles and helper functions; infrastructure tables (audit, outbox, processed events, idempotency); audit service; event publisher and dispatcher; logging; telemetry; health endpoints; CI pipeline; local development environment.
Out of scope (and where it goes): users, login and sessions (SDD-02); the tenants and firms tables and the real tenant resolver (SDD-03); any business table (SDD-04 onward); the Angular shell (SDD-24); cloud provisioning (SDD-25).
Traceability: REQ-NFR, REQ-COMP (audit trail), REQ-INTEG (event and adapter groundwork).

5. Application bootstrap
SDD-01-FR-020 (api). apps/api MUST: use the Fastify adapter; set global prefix api/v1 for all routes except health/live and health/ready; register @fastify/helmet with default options; register @fastify/cors with origins from CORS_ALLOWED_ORIGINS and credentials true; set the body limit from HTTP_BODY_LIMIT_BYTES; register a global ValidationPipe with whitelist: true, forbidNonWhitelisted: true, forbidUnknownValues: true, transform: true; register the global exception filter from section 7; enable shutdown hooks.
SDD-01-FR-021 (shutdown). On SIGTERM or SIGINT the api MUST stop accepting new connections, wait for in-flight requests for at most 25 seconds, close the database pool and Redis connection, then exit with code 0. If 25 seconds pass, it MUST exit with code 1.
SDD-01-FR-022 (worker). apps/worker MUST start a NestJS application context (no public HTTP server), start the outbox dispatcher (section 10), and expose only the health endpoints on WORKER_HEALTH_PORT. Shutdown behaves as FR-021 and additionally waits for the in-progress dispatch batch to finish.
SDD-01-FR-023 (OpenAPI). The api MUST serve the generated OpenAPI 3.1 document at GET /api/v1/openapi.json when NODE_ENV is development or test, and MUST NOT serve it in staging or production.
Tests: TC-01-005 to TC-01-009.

SDD-01-FR-041 (response envelope). Every error response MUST have Content-Type: application/json and this shape:
{  "error": {    "code": "VALIDATION_FAILED",    "message": "The request is invalid.",    "details": [ { "path": "email", "code": "IS_EMAIL", "message": "email must be an email" } ],    "requestId": "0192f0a2-7c1e-7b3a-9d11-5e0c2f6a7b10",    "traceId": "4bf92f3577b34da6a3ce929d0e0e4736"  }}

SDD-01-FR-042 (filter mapping). One global exception filter MUST map: AppError to its code and status; Nest BadRequestException produced by the ValidationPipe to VALIDATION_FAILED; a body larger than HTTP_BODY_LIMIT_BYTES to status 413 with VALIDATION_FAILED and detail code PAYLOAD_TOO_LARGE; Nest NotFoundException to NOT_FOUND; Nest ThrottlerException to RATE_LIMITED with header Retry-After in seconds; any other error to INTERNAL_ERROR. Statuses 500 and above MUST be logged at level error with the stack. Statuses 400 to 499 MUST be logged at level warn without the stack.

8. API conventions (implemented as shared building blocks)
SDD-01-FR-050 (pagination). libs/platform/http MUST export PageQueryDto (limit: integer 1 to 100, default 25; cursor: optional string up to 512 characters) and Page<T> with this response shape: { data: T[], page: { limit: number, nextCursor: string or null } }. A cursor is base64url of the UTF-8 JSON { v: 1, k: [sort values], id: UUID }. An undecodable cursor MUST raise VALIDATION_FAILED with detail path cursor and code INVALID_CURSOR.
SDD-01-FR-051 (idempotency). A decorator @Idempotent() on a POST route MUST apply the behaviour in section 10.4 when header Idempotency-Key is present (string 8 to 128 characters of A-Za-z0-9_-). Routes that SDDs mark as idempotency-required MUST reject a missing key with VALIDATION_FAILED, path Idempotency-Key, code REQUIRED.
SDD-01-FR-052 (optimistic concurrency). A decorator @RequireIfMatch() MUST read header If-Match in the form "<integer>" (double quotes included). Missing header raises PRECONDITION_REQUIRED. Malformed header raises VALIDATION_FAILED, path If-Match, code INVALID_FORMAT. Responses for single records MUST include header ETag: "<version>". Update statements MUST use WHERE id = $1 AND version = $2; zero rows updated raises VERSION_CONFLICT.
SDD-01-FR-053 (rate limit). The api MUST register @nestjs/throttler with Redis storage: authenticated requests limited per user id to RATE_LIMIT_USER_PER_MIN per 60 seconds; unauthenticated requests limited per IP to RATE_LIMIT_IP_PER_MIN per 60 seconds. Health endpoints are exempt.
SDD-01-FR-054 (representations). All JSON responses MUST follow: dates-with-time as ISO 8601 UTC with milliseconds (2026-07-01T09:30:00.123Z); dates-without-time as YYYY-MM-DD; identifiers as lowercase UUID strings; money as integer cents; enumerations as lowercase snake_case strings; absent values as null (every declared field is always present). For PATCH requests a missing field means unchanged; null clears the field only where the SDD marks it nullable, otherwise VALIDATION_FAILED.
Tests: TC-01-020 to TC-01-024.

9.6 Database access layer
SDD-01-FR-063 libs/platform/db is the only code allowed to import pg and kysely. It MUST export TenantDb with one method: withTransaction<T>(fn: (tx: TenantTransaction) => Promise<T>, options?: { tenantId?: UUID }): Promise<T>. It MUST: obtain tenantId from options or from RequestContextService.requireTenantId(); open a transaction; run SELECT set_config('app.tenant_id', $1, true); run SET LOCAL statement_timeout and SET LOCAL idle_in_transaction_session_timeout with the configured values; run fn; commit on success; roll back on any thrown error and rethrow it. Nested calls to withTransaction inside fn MUST throw INTERNAL_ERROR (no nested transactions).
SDD-01-FR-064 libs/platform/db MUST also export DispatcherDb (pool using DATABASE_DISPATCHER_URL) used only by the outbox dispatcher, and MigratorConnection used only by tools. There is no other way to run SQL.

10. Audit, events, idempotency behaviour
10.1 Canonical JSON
Canonical JSON is UTF-8 text with no whitespace, object keys sorted ascending by UTF-16 code units at every depth, arrays in given order, strings and numbers as produced by JSON.stringify, absent keys omitted, null kept. libs/shared/kernel MUST export canonicalJson(value: unknown): string.
10.2 Audit service
SDD-01-FR-070 libs/platform/audit MUST export AuditService.record(entry, tx) where entry = { action, entityType, entityId or null, payload, actor? }. actor defaults to the context actor. tx is the TenantTransaction of the business change; the audit row is therefore committed or rolled back with it.
SDD-01-FR-071 (algorithm). record MUST execute:
Validate action against the pattern in 9.2; invalid raises INTERNAL_ERROR.
Reject payloads containing, at any depth, a key (case-insensitive) in this list: password, passwordhash, token, secret, apikey, authorization, cookie, idnumber, documentnumber, dateofbirth, imagedata. Raise AUDIT_PAYLOAD_FORBIDDEN.
Reject payloads whose canonicalJson is longer than 16384 bytes. Raise AUDIT_PAYLOAD_TOO_LARGE.
INSERT INTO audit_chain_heads (tenant_id) VALUES ($tenant) ON CONFLICT DO NOTHING.
SELECT last_seq, last_hash FROM audit_chain_heads WHERE tenant_id = $tenant FOR UPDATE.
seq = last_seq + 1; occurredAt = Clock.now() formatted YYYY-MM-DDTHH:mm:ss.SSSZ.
Build the object { action, actor_id, actor_type, entity_id, entity_type, occurred_at, payload, seq, tenant_id }; hash = SHA-256(last_hash bytes followed by UTF-8 bytes of canonicalJson(object)).
Insert the audit_events row with prev_hash = last_hash and the computed hash.
UPDATE audit_chain_heads SET last_seq = $seq, last_hash = $hash WHERE tenant_id = $tenant.
Consequence, accepted by design: audit writes within one tenant are serialized by the row lock in step 5.
SDD-01-FR-072 (verifier). AuditChainVerifier.verify(tenantId) MUST read audit_events in ascending seq pages of 1000, recompute each hash with the algorithm above starting from 32 zero bytes, and return { valid, checked, firstBrokenSeq }. tools/verify-audit-chain MUST wrap it as a CLI taking --tenant <uuid> and exit with code 0 if valid, 2 if broken.
10.3 Event publisher and dispatcher
SDD-01-FR-073 (publish). EventPublisher.publish(input, tx) with input = { name, version, aggregateType, aggregateId, payload } MUST insert one outbox_events row inside tx with occurred_at = Clock.now(). Payloads over 65536 bytes raise EVENT_PAYLOAD_TOO_LARGE.
SDD-01-FR-074 (handlers). Handlers register with the decorator @OnDomainEvent(name, version) on a method of a Nest provider; the handler name is <ClassName>.<methodName>. Two handlers with the same handler name are a startup error.
SDD-01-FR-075 (dispatcher loop). In the worker, every OUTBOX_POLL_INTERVAL_MS (and immediately again if the last claim returned a full batch) the dispatcher MUST:
Using DispatcherDb, in one statement claim up to OUTBOX_BATCH_SIZE rows: UPDATE outbox_events SET locked_until = now() + OUTBOX_LEASE_SECONDS WHERE id IN (SELECT id FROM outbox_events WHERE status = 'pending' AND next_attempt_at <= now() AND (locked_until IS NULL OR locked_until < now()) ORDER BY occurred_at, id LIMIT $batch FOR UPDATE SKIP LOCKED) RETURNING *.
For each claimed event, find handlers registered for the exact (event_name, event_version).
For each handler, run TenantDb.withTransaction with tenantId = event.tenant_id, actor { type: 'system', id: null }: insert into processed_events (ON CONFLICT DO NOTHING RETURNING event_id); if no row returned, skip (already processed); else run the handler in the same transaction.
If every handler succeeded (or none are registered): set status = 'published', published_at = now(), locked_until = NULL.
If any handler failed: set attempts = attempts + 1, last_error to the first 1000 characters of the error message, locked_until = NULL, and next_attempt_at = now() + delay where delay for attempt number 1 to 7 is 5 s, 30 s, 2 min, 10 min, 30 min, 1 h, 3 h. When attempts reaches 8, set status = 'dead' instead and log level error with event id and name.
Guarantees: at least once delivery; no ordering guarantee between events; handlers MUST be written to tolerate repeats and reordering.
10.4 Idempotency
SDD-01-FR-076 For a request with Idempotency-Key on an @Idempotent() route, the interceptor MUST: compute request_hash; in a transaction insert into idempotency_keys with status processing and expires_at; on primary key conflict load the existing row and apply: if request_hash differs raise IDEMPOTENCY_KEY_REUSED; if status is processing raise IDEMPOTENCY_IN_PROGRESS with header Retry-After: 2; if completed return the stored response_status and response_body with header Idempotency-Replayed: true. After the handler finishes, store the status and body (success and 4xx results; 5xx results delete the row instead so the client may retry). A scheduled job in the worker MUST delete rows with expires_at < now() every 15 minutes, using one transaction per tenant.
Tests: TC-01-033 to TC-01-048.
